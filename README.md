# BACKSTAGE — Fan Story Studio Prototype

림버스 컴퍼니 팬 스토리 제작용 프런트엔드 프로토타입입니다. React + TypeScript + Vite로 구성되어 있습니다.

## 실행 방법

Node.js 20 이상 권장.

```bash
npm install
npm run dev
```

터미널에 표시되는 로컬 주소를 브라우저에서 여세요.

## 빌드 확인

```bash
npm run build
npm run preview
```

## 이미지 업로드 동작 방식 — 꼭 읽어 주세요

- 업로드 시 브라우저가 원본 파일을 읽고 이미지 데이터를 프로젝트 안에 복사해 저장합니다. 프로젝트는 원본 이미지 파일의 경로를 참조하지 않습니다.
- 따라서 **업로드한 뒤 원본 파일을 이동하거나 삭제해도, 업로드한 이미지 사본은 바뀌거나 삭제되지 않는 것이 정상**입니다.
- 원본 파일의 수정 사항을 자동으로 따라가는 방식은 아닙니다. 이미지가 바뀌면 에셋 보관함에서 기존 에셋을 삭제하고 수정된 이미지를 다시 업로드한 다음 작품을 저장하세요.
- 이미지 업로드 후에는 `저장`을 눌러야 작품 데이터에 반영됩니다. 업로드 이미지가 크면 브라우저 저장소 용량 제한 때문에 저장에 실패할 수 있습니다. 이 경우 이미지 해상도/용량을 줄이거나 작품 JSON을 내보내 백업하세요.
- JSON 내보내기에는 사용자 업로드 이미지 데이터가 포함됩니다. 기본 내장 에셋은 앱에 포함되어 있으므로 JSON에 중복 저장하지 않습니다.
- 배경 기본 에셋 일부는 외부 Unsplash URL을 사용하므로 인터넷 연결이 필요합니다.

## GitHub Pages 배포

이 저장소에는 GitHub Pages 자동 배포 워크플로가 포함되어 있습니다.

1. ZIP 압축을 풉니다.
2. GitHub에서 새 **Public** 또는 **Private** 저장소를 만듭니다. 예: `backstage`.
3. 압축을 푼 `backstage_fixed` 폴더 **안의 파일과 폴더 전부**를 저장소 최상위에 업로드합니다. `src`, `public`, `package.json`, `vite.config.ts`, `.github` 등이 최상위에 보여야 합니다. `backstage_fixed` 폴더 자체를 한 겹 더 올리지 마세요.
4. 저장소의 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
5. `main` 브랜치에 파일을 커밋합니다. **Actions** 탭에서 `Deploy BACKSTAGE to GitHub Pages` 작업이 완료될 때까지 기다립니다.
6. 성공하면 **Settings → Pages**에 표시된 사이트 주소로 접속합니다. 일반적으로 `https://<사용자명>.github.io/<저장소명>/` 형태입니다.

이후 코드를 수정해 `main`에 올릴 때마다 자동으로 다시 배포됩니다.

## 데이터와 개인정보

- 현재 버전에는 계정, 서버 저장, 온라인 작품 공유 기능이 없습니다.
- 작품 목록은 해당 브라우저의 `localStorage`에 저장됩니다. 브라우저 데이터 삭제, 다른 브라우저/기기 사용 시 자동으로 옮겨지지 않습니다.
- 공유 및 백업은 편집기의 JSON 내보내기/불러오기 기능을 사용하세요.
- 브라우저 저장소는 용량 제한이 있습니다. 이 버전은 개인용 프로토타입이며 대용량 이미지의 장기 저장소를 대체하지 않습니다.
- 팬메이드 배포 시 내장된 캐릭터 이미지와 기타 지식재산권의 이용 조건을 별도로 확인하세요.
